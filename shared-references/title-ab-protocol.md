# Title A/B Scoring（标题 A/B 评分协议）

被 `cheat-essay-predict` 引用。这是 predict 流程嵌入的 Phase 2.5 规范。

---

## 为什么有这个 phase

公众号 TH（Title Hook）维度对实际表现的影响很大——平台权重表的 40% 打开率几乎全由标题决定。但 TH 在 v0 rubric 里是一个标量分数，**掩盖了一个真实场景**：

作者写完 draft 时，通常已经在脑子里有 2-3 个标题候选。直接打 TH=4 没有体现这个选择过程的信号——选错标题这 4 可能变 2。

**这个 phase 把「标题选择」显式化**：让用户给 2-3 个候选标题，工具对每个独立打 TH 分 + 推荐选哪个。最终 prediction 文件里记录用户实际选了哪个 + 其他备选的得分——这是后续校准 TH 维度的关键数据。

---

## 何时触发

**predict v1 时必触发**：写 prediction 的 Phase 2.5（在打 7 维分之后、写预测主体之前）。

**predict v2 时**：仅当 finalize 阶段检测到标题变化（`title_changed: true`）才触发——重新给新标题打 TH。

## 输入

| 必填 | 来源 |
|---|---|
| 草稿全文 | 用户参数 |
| 2-3 个候选标题 | 询问用户提供 |
| 当前 rubric | rubric_notes.md，取 TH 维度定义 |

如果用户只给 1 个标题：
- **不主动生成备选**——违反盲预测原则（AI 生成的标题 = 工具部分代写了你的判断对象）
- 询问"你心里只有这一个？还是有备选但懒得说？"
  - 只有一个 → 仍然走单标题路径，给一个 TH 分 + 列出"你可能没想到的方向"作为思考线索（**不打分这些方向**）
  - 有备选懒得说 → 鼓励用户给出，强调"你才知道你的口吻"

## 输出格式

写到 prediction 文件的 `## 输入快照` 段之后、`## 预测 v1` 段之前：

```markdown
## 标题 A/B 评分

**候选数**: 3
**选择者**: user（最终选择由用户做，工具仅推荐）

| 候选 | TH 评分 | 优势 | 短板 | 推荐? |
|---|---|---|---|---|
| 「停止期待，是我对他最后的温柔」 | 4 | 反差 + 隐含承诺 | "温柔"略软，不够锋利 | 推荐 |
| 「他给的不是爱，是配合你期待演的戏」 | 5 | 命名 + 反主流 + 独立站立 | 略冲，可能吓退一部分读者 | 强烈推荐 |
| 「我们之间的关系，本质是 OOO」 | 2 | 制造好奇 | 留白过多，标题党感 | 不推荐 |

**推荐**: 候选 #2（评分 5，命名了「关系是表演」这个反主流共识）

**用户最终选择**: <用户填入>
```

**关键约束**：
- "推荐"是工具建议，不是决定——`用户最终选择`字段由用户在 Phase 2.5 结束前确认
- 工具不可以替用户填这个字段
- prediction 写入磁盘后，这段进入 immutable 范围

## 评分锚点（每个候选独立打 TH 1-5）

照搬 wechat-essay-zero.md 的 TH 维度定义，但拆得更细：

| 1-5 | 描述 |
|---|---|
| 1 | 描述性流水（"今天发生的一件事"） |
| 2 | 有信息密度但平淡（"我和父亲的一次对话"） |
| 3 | 一个具体角度但不锋利（"为什么我们害怕承诺"） |
| 4 | 反差 / 反主流 / 隐含承诺 三者占其一 |
| 5 | 三者占其二以上 + 独立站立力强（脱离正文也能让陌生人 get） |

**两个反 pattern 警告**：
- **标题党**：5 分标题但全文兑现 ≤ 2 → 标 `clickbait_risk: high`，复盘时记得检查
- **过度修饰**：标题用了 3 个以上感叹号 / 反问号 / 数字 → 算法可能识别为 "营销味"，触发限流

## 评分时严禁的事

- ❌ 不主动改写候选标题
- ❌ 不告诉用户"我帮你想了第 4 个候选"
- ❌ 不打分时只看字数 / 表面修辞——必须看是否带反差、反主流、独立站立力
- ❌ 不"安慰式打分"——所有候选 ≥4 是逃避评分，永远要拉开梯度

## 与 retro 的对接

复盘时 cheat-essay-retro 读这一段：
- 实际表现 vs 推荐选择 → 判断 TH 维度的 rubric 准确性
- 如果用户选了**不被推荐的候选**但跑得很好 → rubric 反 pattern，写到 rubric_notes.md「未来观察」
- 如果用户选了**推荐候选**但跑得差 → 检查是否触发 `clickbait_risk` 反 pattern

## 实施提示给阶段 6

在 cheat-essay-predict 的 Workflow 里加 Phase 2.5（在原 Phase 2「打 7 维分」之后、Phase 3「写预测主体」之前），按本协议执行。

Phase 2.5 输出的 markdown 段直接写入 prediction 文件（在 `## 预测 v1` 之前）——不破坏 immutable 边界，因为 hook 只锁 `## 预测 v1` 段之后。
