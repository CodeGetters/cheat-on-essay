# Publish Timing Protocol（发布时段评分协议）

被 `cheat-essay-predict` 引用。这是 predict 流程嵌入的 Phase 6 metadata 规范。

---

## 为什么有这个 phase

公众号文章的「打开率」（平台权重 40%）受发布时段强影响——同一篇文章早 7 点发 vs 凌晨 2 点发，触达和点开率可以差 3-5 倍。

但发布时段不是"随便选"能优化的——它和**议题类型 + 读者画像**强耦合。情感文章晚 22 点发优于早 7 点（睡前情绪敏感），通勤干货文晚发反而无效（用户已下班）。

**这个 phase 让发布时段成为 prediction 的显式元数据**——记录"打算什么时候发"，复盘时验证时段假设。

---

## 何时触发

**predict v1 时**：Phase 6（写元数据）一并询问，记入 prediction header。

**finalize 时**：如果定稿改了议题类型，触发重判（与 v2 一起算）。

## 三个黄金时段

基于公众号通用阅读行为（**不是普世真理，是 v0 的起步参考——用户可在 init 时校准**）：

| 时段 | 场景 | 适用议题类型 |
|---|---|---|
| **早 7-8 点** | 通勤路上、起床浏览 | 信息密度型（干货 / 行业分析 / 时事点评）—— 用户主动找信息 |
| **中午 12-13 点** | 午休碎片时间 | 轻量型（短文 / 小议题 / 段子型时评）—— 用户找消遣 |
| **晚 20-22 点** | 睡前躺平 | 情感深度型（个人随笔 / 情感叙事 / 深度长文）—— 用户开放接收情绪 |

**第四个时段（非推荐）**：早 5-6 / 凌晨 1-2 / 周末白天，**默认不推荐**——除非用户的账号画像确认这些时段有阅读高峰。

## 议题 → 时段映射表

把 cheat-essay-init Q1 的 content_form 映射到推荐时段：

| content_form | 推荐时段 | 理由 |
|---|---|---|
| `opinion-essay`（议题观点 / 时评） | 早 7-8 / 晚 20-22 二选一 | 看议题密度：信息密度高走早，情感浓度高走晚 |
| `knowledge-deep`（深度知识 / 长文科普） | 早 7-8 | 通勤"我要学点东西"的主动求知状态 |
| `personal-narrative`（个人随笔 / 情感叙事） | 晚 20-22 | 睡前情绪开放期 |
| `tutorial-practical`（教程实操 / 工具分享） | 早 7-8 / 周末上午 | 用户主动找工具的时段 |
| `news-commentary`（新闻速递 / 热点点评） | **不能等时段**，越早越好（首发权重）| 时效性 > 时段画像 |
| `mixed` | 早 7-8 默认 | 不确定走最稳的通勤档 |

## 输出格式

写到 prediction 文件的 metadata header（在 `## 输入快照` 之前）：

```markdown
**Publish Timing**: 推荐 晚 20-22 / 用户计划 晚 21:30
**Timing Rubric**: 议题类型 personal-narrative → 晚档默认（情绪开放期匹配 EG=4 颗粒度）
**Timing Confidence**: 🟡 (v0 议题映射表为起步参考，未在你账号校准)
```

字段说明：
- `Publish Timing`：推荐时段 + 用户实际计划时段（两个都记，便于复盘对比）
- `Timing Rubric`：推荐理由的一句话简述
- `Timing Confidence`：🟢 = 用户账号校准 ≥5 篇并验证；🟡 = 沿用 v0 起步表；🔴 = 用户选了**完全反向**的时段（如情感文早 7 发）

## 几条不推荐 ≠ 拒绝

工具**推荐时段**但**不强制**：

- 用户可以选任何时段——只是会被工具标 confidence 低 + 复盘时单独看
- 用户选反向时段（如情感文早 7 发）→ 工具询问理由："这是基于你账号的读者画像吗？还是有别的原因？"
  - 用户给出有效理由（"我的读者主要是早醒族"）→ Confidence 标 🟡 但接受
  - 用户没理由 → 工具显示"建议改回晚档，但你说了算" + 在 prediction 标 `timing_risk: high`

## 校准路径

用户跑出 5+ 篇真实复盘后，cheat-essay-bump 可以做「时段权重重校」：

- 把所有 prediction 按时段分桶 → 看每桶的平均阅读 / 在看率 / 涨粉率
- 如果某个时段显著优于推荐（如该用户其实凌晨 1 点跑得最好）→ 更新议题映射表
- bump 后，新的 prediction 用校准后的推荐表

**重要**：bump 时段权重要慎重——时段是高方差变量（热点周期 / 节假日 / 算法波动都影响），建议 N≥10 才动。

## 用户自定义读者画像（可选）

用户在 init 时可以提供自己的「读者画像」覆盖默认表：

```json
{
  "reader_profile": {
    "active_hours": [7, 8, 12, 21, 22],  // 用户后台「读者活跃时段」分布的 top 5
    "dominant_form": "personal-narrative",
    "geo": "一线城市",
    "age_band": "25-35"
  }
}
```

如果有 reader_profile：
- `active_hours` 直接替代「三个黄金时段」推荐
- `dominant_form` 用于 timing 推荐时的议题类型偏移

如果没 reader_profile（v0 默认情况）：
- 走通用三档表
- cheat-essay-status 持续提示「配置读者画像可以让 timing 推荐更准」

## Refusals

- 「我每次都晚 22 点发，工具别再问了」 → 允许在 init 设 `skip_timing_phase: true`，跳过 Phase 6 timing 询问。但提示用户：跳过等于不学习时段信号，bump 时这个维度永远不会校准
- 「帮我算最佳时段，我直接照做」 → 不能。时段是用户决定的事——工具只能推荐和打分，不能"自动设定"

## 实施提示给阶段 6

在 cheat-essay-predict 的 Workflow 加 Phase 6（在原 Phase 6 写状态之前 / 之后），按本协议执行。

Phase 6 的输出 markdown 直接写入 prediction header 段（在 `## 输入快照` 之前）——header 段不在 immutable 锁的范围（hook 只锁 `## 预测 v1` 之后）。
