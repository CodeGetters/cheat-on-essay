# /cheat-essay-quotes — 金句抽取与评分

公众号 QD 维度的衍生工具——把"全文哪些句子是截图传播的最佳候选"显式化。

## 为什么需要这个 skill

公众号文章的二次传播路径有两条：
1. **整篇分享** → 朋友圈 / 群聊点链接打开。门槛高，分享率天花板低
2. **截图分享** → 选一段文字截图发到朋友圈 / 群聊。门槛低，传播倍数高

第 2 条路径的核心是「**能否独立站立的金句**」。但用户自己看自己的稿子时，很容易看不见——文章在脑子里是有上下文的，截图金句要在没上下文时也站得住。

这个 skill 把"全文哪几句是金句"的判断显式化：
- 输入：一篇 draft / 一段文字
- 输出：N 个候选金句 + 各自的传播力评分 + 建议如何修改让它更"截图友好"

## 与 cheat-essay-predict 的关系

- **不替代** predict 的 QD 维度打分——predict 的 QD 是文章整体的金句密度（0-5），quotes 是具体句子级别的候选库
- **不是 predict 必经**——用户可以单独调；典型场景：写完 draft 自检 / 复盘时回看是否漏了好句 / 想从老稿子里挑可二次传播的金句
- **输出可被 predict 引用**——`cheat-essay-quotes draft.md --write-to draft.quotes.md` 后，predict 时可以读 quotes.md 作为 QD 维度证据

## Overview

```
[用户：抽金句 drafts/2026-05-12_abc123_停止期待.md]
  ↓
[Phase 0: 读 draft 内容 + 拿配置]
  ↓
[Phase 1: 候选筛选（按四个特征过粗筛）]
  ↓
[Phase 2: 候选评分（5 维传播力评分）]
  ↓
[Phase 3: 排序 + Top N 推荐]
  ↓
[Phase 4: 可选——给「改进建议」]
  ↓
[Phase 5: 可选落盘（--write-to）]
```

## Constants

- **DEFAULT_TOP_N = 8** — 默认推荐 top 8 候选
- **MIN_LENGTH = 8** — 候选金句最少 8 字符
- **MAX_LENGTH = 50** — 候选金句最多 50 字符（朋友圈截图常用宽度）
- **MIN_SCORE_TO_SUGGEST = 6.0** — 低于此分不进 top 列表

## Inputs

| 必填 | 来源 |
|---|---|
| `<draft-path>` | 用户参数；缺失则读 `state.in_progress_session.file` 反推 draft |
| `rubric_notes.md` | 取当前 rubric 版本上下文（QD 维度的最新定义） |

## Workflow

### Phase 0: 读取

读 draft 全文。如果 draft 路径无效 → 提示用户给正确路径，不创建新文件。

### Phase 1: 候选筛选（粗筛）

按四个特征扫全文，标出所有满足任一特征的句子（按句号 / 问号 / 感叹号切分）：

| 特征 | 信号 |
|---|---|
| **断言型** | "X 不是 Y，是 Z" / "X 的本质是 Y" / 命名一个现象 |
| **反差型** | "我们以为 X，其实 Y" / "X 看似 Y，实际 Z" |
| **可识别情绪** | 具体的"我也是"细节 / 反讽 / 自嘲（不是抽象情绪词） |
| **结构性观察** | 命名一个读者意识到但说不出的 pattern |

排除明显不适合的：
- 过短（< 8 字）—— 站不住
- 过长（> 50 字）—— 截图截不下
- 包含明显上下文依赖词（"这种"、"上面说的"、"如前所述"）—— 离开上下文失败
- 是引用别人的话（除非引语本身就是金句）

通常一篇 2000 字稿子粗筛出 10-25 个候选。

### Phase 2: 候选评分（5 维传播力）

对每个候选用 5 维打 1-5 分：

| 维度 | 简称 | 含义 |
|---|---|---|
| **独立站立力** | **IS** | 离开原文上下文，这句还能让陌生人 get 到吗？ |
| **自我识别度** | **SI** | 读者能否「啊我也是 / 我也这样」 |
| **可截图视觉** | **VG** | 长度 + 节奏 + 标点是否适合朋友圈方形截图 |
| **可转述压缩** | **CT** | 群聊里有人转述时是否会保持原意（不是越改越散） |
| **议题敏感度** | **TS** | 是否触及一个当下被讨论的议题 / 命名一个集体感受 |

总分 = `(IS + SI + VG + CT + TS) / 5 × 2.0`，范围 0-10。

**关键纪律**：
- VG 不能仅看长度——节奏（短促 vs 拖沓）和标点（句号 vs 问号 vs 破折号）影响视觉感
- TS 在不同时间打分会不同（议题周期），打分时标记当前日期
- 不要把"金句感"和"哲学感"混淆——哲学感强但 SI=1 的句子（如"存在即合理"）实际传播很差

### Phase 3: 排序 + Top N

按总分降序，过滤 < `MIN_SCORE_TO_SUGGEST` 的：

```
🪞 从 drafts/2026-05-12_abc123_停止期待.md 抽出 N 个候选金句：

| # | 候选 | 总分 | IS / SI / VG / CT / TS | 位置 |
|---|---|---|---|---|
| 1 | 停止期待不是冷漠，是终于看清你不是关系的责任人 | 9.0 | 5 / 5 / 4 / 5 / 5 | 第 7 段倒数第 2 句 |
| 2 | 我们以为放下是不再想他，其实是不再为他的沉默找解释 | 8.4 | 5 / 5 / 4 / 4 / 4 | 第 3 段中段 |
| 3 | ...（按分排） |

低于 6.0 的 X 条已折叠（要看回 "show all"）。

🎯 推荐：
- 朋友圈截图首选：#1（独立站立 + 自我识别都满分）
- 文末收束首选：#3（短促 + 有"留白让读者接"的余地）
- 中段加粗首选：#2（有「我们以为...其实...」的反差结构）
```

### Phase 4: 改进建议（可选）

对 top 3-5 候选给一句改进建议（如果有明显改进空间）：

```
💡 改进建议（不强求采纳）：

#2 候选「我们以为放下是不再想他，其实是不再为他的沉默找解释」
   - 当前 VG=4（48 字偏长）
   - 候选修改：「放下不是不再想他，是不再替他的沉默找解释」（38 字，VG +1）
   - 提示：这只是建议——你的原句节奏更重，修改版更轻。**选哪个看你的口吻**

#4 候选「他给的不是爱，是配合你期待的角色扮演」
   - 当前 CT=3（"角色扮演"有点抽象，转述时易丢）
   - 候选修改：「他给的不是爱，是配合你期待演的戏」（CT +1）
   - 提示：这只是建议——原句更精准但更冷
```

**关键纪律**：
- 改进建议必须明确标注是 suggestion 不是 demand
- 永远说"原句也好，看你口吻"——不要让工具变成 AI 改文笔的入侵
- 不主动给「补一句金句」之类的内容生成建议——quotes 是抽取工具不是创作工具

### Phase 5: 落盘（可选）

如果用户给了 `--write-to <path>` 参数：

写到 `<path>`（默认 `<draft-path>.quotes.md`）：

```markdown
# Quote candidates — <draft 标题>

**Draft**: drafts/2026-05-12_abc123_停止期待.md
**抽取时间**: 2026-05-12T16:00:00+08:00
**Rubric version**: v0
**Total candidates**: N
**Top N shown**: 8

---

## Top 8 候选

| # | 候选 | 总分 | IS / SI / VG / CT / TS | 位置 |
|---|---|---|---|---|
| 1 | ... | 9.0 | 5/5/4/5/5 | 第 7 段倒数第 2 句 |

## 改进建议

#2 → ...

## 完整候选池（含低分）

[折叠所有 ≥ 6 分的候选，包括没进 top]
```

落盘后告诉用户："quotes.md 已写到 X。cheat-essay-predict 跑预测时可以引用这个文件作为 QD 维度证据。"

## Key Rules

1. **不代写金句**——只从用户原文抽取候选，不主动生成新句子
2. **不修改 draft**——quotes.md 是旁路文件，永不动 draft 本身
3. **改进建议可选** + **明确标 suggestion**——不让工具变成 AI 改文笔
4. **5 维评分要透明**——不只给总分，列出每维分数让用户判断
5. **不与 predict 的 QD 维度冲突**——quotes 是句子级别，predict 的 QD 是文章级别
6. **不计入校准数据**——quotes 的评分不进 calibration_samples，不影响 bump

## Refusals

- 「帮我从空白中创作 5 个金句」 → 拒绝。本 skill 是抽取工具，不是 AI 写作工具
- 「把所有 < 6 分的候选都删了」 → 拒绝。低分候选要保留在 quotes.md 完整池里，用户可能想看
- 「跳过评分直接列出全部候选」 → 允许（`--no-score`），但提示用户后续仍需要评分才有用
- 「金句改进建议直接帮我替换掉原文」 → 拒绝。建议是 suggestion，替换是用户决策

## Refusal: 跨越「盲预测」边界

特别警惕：用户 publish 后可能想用 quotes 反向校验「我之前写的金句是不是被截图传播了」。这是 retro 阶段的事，不是 quotes 的事——quotes 是 pre-publish 的预判工具。

- 「这篇已经发出去了，帮我看看截图传播率」 → 拒绝。请走 `/cheat-essay-retro`

## Integration

- 与 `cheat-essay-score`：quotes 是 score 的「下钻」工具——score 给文章整体 QD=4，quotes 给句子级别的"具体是哪些句子让 QD 这么高"
- 与 `cheat-essay-predict`：predict 的 QD 推理段可以引用 quotes.md 的 top 候选作为证据
- 与 `cheat-essay-retro`：复盘时如果实际 top 评论里出现了金句的引用 → 验证 quotes 抽取准确性（rubric 信号）
- 不与 `cheat-essay-bump` 直接交互——quotes 的评分不进校准池

## 何时跑 quotes

| 时机 | 价值 |
|---|---|
| 写完 draft 自检 | 高——能立刻看出"我以为有金句但其实没有"的盲点 |
| predict 之前 | 中——给 QD 维度打分提供句子级证据 |
| finalize 改稿后 | 中——验证改稿是否提升了金句质量 |
| 复盘时回看 | 中——对比"我当时认为的金句"vs"读者实际截图传播的金句" |
| 从老稿子挖二次传播素材 | 高——有些金句当时没被读者发现，后来可以单独抽出来发朋友圈 |
